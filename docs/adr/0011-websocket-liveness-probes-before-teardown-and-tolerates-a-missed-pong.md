# WebSocket liveness: probe before teardown, and tolerate one missed pong

Neither end of the relay WebSocket tears a connection down on silence alone. The client, when its stale threshold is exceeded, first sends a ping and waits a short grace period (~5 s), and only tears down if nothing arrived. The page also triggers that probe on every return to visibility (`noteVisible()`). The server reaper terminates only after TWO consecutive missed pongs, and treats ANY inbound frame as proof of life, not only `pong`.

The primary client is a phone. When a backgrounded page thaws (most often after the file picker or camera, which deliberately skips the 8 s suspend), timers fire before the frames queued during the freeze are dispatched. So a "silent for 45 s" verdict is routinely false, and acting on it turns an instant return into a reconnect plus resync. A trigger based only on a wall-clock jump was rejected: with 25 s ticks and a 45 s mid-turn threshold, a freeze-induced gap of 45-50 s is not a ">2× interval" jump, yet it still crosses the threshold. The cost is that a genuinely dead socket is detected about one grace period later on the client and one interval later on the server, and a vanished viewer counts as present for up to ~3× the heartbeat interval. Same-tab reconnects are still evicted immediately by `clientKey`.
