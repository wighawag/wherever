# On-device conversation cache: on by default, keyed by the server that delivered it

To show a conversation instantly after the OS kills the PWA, the web keeps a bounded IndexedDB cache of recently viewed conversations (5 sessions, ~2 MB each), ON by default with no opt-in toggle. The owner explicitly accepted that sensitive content, including tool output, is stored on the device.

Each cached conversation carries a `serverKey` (`host:port` plus a synchronous non-crypto hash of the token) STAMPED from the socket that delivered it, never re-derived from the current settings. Connection Settings save host, port and token without reconnecting, and the client's automatic reconnect then runs against the edited config while the store still holds the old server's conversation. A key derived at write time would therefore file one server's conversation under another's. When a connect computes a key different from the stamp, the client wipes rather than preserves, and drops any pending rejoin. Instead of remembering a "previous server", every connect calls `retainOnly(currentKey)`, which also covers reloads; both Disconnect actions clear the cache outright. The hash is synchronous because `connect()` is synchronous and `crypto.subtle` is async and unavailable on plain-http LAN origins.

A cached conversation is evicted only when the server refuses the load itself (an untagged `session_error` before any `session_created`), never on a missing folder or a failed cold agent build. Those arrive after an authoritative paint and must keep today's readable-but-blocked view.
