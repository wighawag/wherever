# Decisions taken while building `closed-sessions-in-search` (2026-11-24)

Recorded per the work contract so a reviewer can ratify or reverse them. Code sites: `server/src/conversation-search.ts` (`ThreadFilter`, `visibility`, `filterThreads`, `filterHits`), the `/search` route in `server/src/index.ts`, `web/src/lib/core/search-request.ts`, `web/src/lib/components/ConversationSearch.svelte`. Documented in `CONTEXT.md` "Conversation search" and `docs/USAGE.md` `GET /search`.

1. **Predicates moved into one options object (`ThreadFilter`)** instead of a fourth positional predicate. The task allowed either; the object keeps call sites readable and gives the date-range task (and any later rule) a place to add a field without reshuffling arguments. `visibility(view, includeClosed)` now returns the filter rather than a closure, and the hit loop moved into an exported pure `filterHits` so `threadTotal` / `hiddenHits` are unit-tested without an index (`server/test/conversation-search-filter.test.ts`).
2. **The closed check runs LAST, on the normalized `sessionPath`.** Last, so `includeClosed` can never bring back a thread dropped by `sessions.ignore`, `sessions.readOnly` or a missing cwd. Normalized, because the store keys entries by `normalizeSessionFile` (the same key `/sessions` uses). Alternative considered: checking closed first (cheaper Set lookup) was rejected because it reads less obviously as "never an escape hatch" and the cost difference is negligible.
3. **Only `includeClosed=1` turns it on** (any other value, including `true`, means off). Matches the panel's `'1'` convention for `localStorage` flags (`wherever-show-closed`) and keeps the parsing as strict as `view=readonly`. Touches the `GET /search` API only.
4. **New key `wherever-search-include-closed`, separate from the sidebar's `wherever-show-closed`.** The spec (story 10) asks for a search-panel toggle; reusing "Show closed" would make one checkbox silently govern two surfaces. One value is shared by the main and read-only search views (the date-range task says the same of its setting). Default off, as the spec requires.
5. **Toggling re-runs immediately**, like `submit()`: a pending debounce is cleared first (so it cannot fire later with the old value), nothing happens below `MIN_QUERY`, and the request goes through `searchConversations`'s existing abort/supersede path. Checked by reading the code path; there is no component test harness for Svelte panels in this repo.
6. **Dimmed rendering** reuses the sidebar's `opacity-50` and adds "· Closed" to the row's meta line and a `Closed ·` title prefix, so a dimmed row is not colour/opacity-only. The hit header is unchanged (a hit may mix closed and open threads).
7. **The pure request builder lives in `web/src/lib/core/search-request.ts`** (`searchRequestParams`, `readIncludeClosed`, `writeIncludeClosed`), so the URL shape and the setting are unit-tested; `session-store.ts`'s `searchConversations` gained an `opts: {includeClosed?}` third argument (an object so `since` can join it in `conversation-search-date-range`).
8. **Changeset bump `minor`**, as the task says (user-visible default change plus a new API parameter).
