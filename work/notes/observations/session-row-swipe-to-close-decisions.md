# session-row-swipe-to-close: decisions and browser check

Date: 2026-11-25. Task `session-row-swipe-to-close` (spec `sidebar-compact-layout`, stories 37 and 38). Thresholds live in `web/src/lib/core/row-swipe.ts` as named constants for the `sidebar-phone-device-pass` to tune.

## Decisions

1. **Three release outcomes, not two.** The task says "releasing past the button's width closes; releasing before it snaps back; tapping the revealed button also closes", and "only one row is revealed at a time". With only close / snap-back, the button would only ever show while the finger is down, so it could never be tapped and "one revealed at a time" would be moot. Chosen: released at least `SWIPE_CLOSE_PX` (= the button width, 86px as in the mockup) left closes; at least `SWIPE_KEEP_REVEALED_PX` (half the button) leaves the row revealed at the button width, with "⊘ Close" tappable (the mockup's frame 1 picture); less snaps back. Alternative: setting `SWIPE_KEEP_REVEALED_PX = SWIPE_CLOSE_PX` gives the literal two-outcome behaviour (no resting reveal). Touches only this row.
2. **Touch pointers only.** `pointerType === 'touch'` starts a gesture; mouse and pen do not swipe (desktop has the hover ⊘). It is not gated on the `md` width, so a touch tablet in the desktop layout also swipes. Alternative: gate on width; rejected because a touch screen has no hover ⊘.
3. **Classifier constants.** Slop 8px (`SWIPE_SLOP_PX`, measured as the movement's length), and a row swipe needs `|dx| >= 1.5 * |dy|` (`SWIPE_DIRECTION_RATIO`). The decision locks for the gesture (`nextSwipeDecision`); a `pass` stops tracking, so a scroll that turns horizontal never moves the row.
4. **`touch-action: pan-y pinch-zoom`** rather than plain `pan-y`, so a pinch that starts on a row still zooms. Only on swipeable rows.
5. **Hiding a reveal.** A tap on the revealed row (its link, ⋯) only hides the button and the click is swallowed. A touch anywhere else (another row, the list) hides it too, and that touch then does what it normally does (a tap on another row opens it). Starting a swipe on another row hides the first. Alternative: swallow the outside tap as well (iOS Mail); not done since a tap elsewhere is a deliberate action.
6. **Rendering.** The row's transform, clip (`overflow-hidden`) and opaque `bg-brand-surface` are applied only while a swipe shows (dragging, revealed, or the 180ms settle), because a transform would make the row the containing block of the ⋯ bottom sheet (`fixed`) and the clip would cut the popover. The swipe never starts while the row's ⋯ menu is open. The button colour is `bg-brand-blue/60` (the mockup's dark blue) with white text.
7. **One revealed row** is a module-level `$state` in `SessionRow.svelte` (`<script module>`), shared by every row in the folder and By-owner views; no prop or store needed. A row that becomes closed or read-only, or unmounts, gives its reveal up.

## Browser check

Built the web (`pnpm web:build`) and ran this branch's real server through the test harness (`server/test/harness.ts`, temp dirs, fake LLM, no token) with 30 sessions written on disk in one folder; drove Chromium headless through playwright-core with CDP touch events (`Input.dispatchTouchEvent`). Then stopped the server and removed the temp files.

- Phone 390x844, touch emulation, in the drawer: a 60px left swipe on the second row left it revealed with "⊘ Close" at the right (as in `phone.png` frame 1) and did not open it (hash unchanged). Swiping another row hid the first (one button on the page). Tapping the revealed button closed that session; the "Closed Session number N. Undo" banner showed and the folder count dropped. A 160px swipe closed the row on release with the banner. A 25px swipe snapped back. A vertical touch drag over the rows scrolled the list (scrollTop 0 to 506) with no reveal. A diagonal drag (40 left, 60 up) did not reveal. A plain tap on a row opened it. A tap on a revealed row hid the button without opening; a tap on another row while one was revealed hid it and opened the tapped row. A tap on the strip right of the drawer still closed the drawer. With "Show closed" on, a 150px swipe on a closed row did nothing.
- Desktop 1280x800, mouse: a mouse drag on a row revealed nothing and closed nothing; hovering a row still shows the one-click ⊘; a click opens the row.
- Read-only page: the harness has no read-only sessions, so not checked by hand; `rowCanSwipe` (unit-tested) returns false for read-only rows.
