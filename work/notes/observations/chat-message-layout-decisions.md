# chat-message-layout: decisions (2026-11-25)

Task `chat-message-layout` (spec `chat-compact-layout`, stories 25 to 31). In-scope choices that a reviewer might not expect:

1. **Tap pins the action row open (touch).** The action row (Copy, Raw / Rendered, Fork) is `opacity-0` and shows on hover or keyboard focus (`focus-within`). A touch screen has no hover, so a tap on a message (not on a link, button or media control, and not one that ends a text selection) pins that message's row open; tapping it again or another message moves / clears it (`revealActions` in `ChatMessageList.svelte`). While hidden, the row is `pointer-coarse:pointer-events-none`, so a tap on an invisible Copy reveals instead of copying. Alternatives: always-visible rows on touch (clutters the phone view the spec is trying to compact), relying on sticky `:hover` after a tap (inconsistent across mobile browsers), long-press (ruled out by the task).
2. **Fork moved into the action row and is hidden until hover / focus / tap.** It used to be an always-visible bordered button inside the user bubble. The task allows "in the action row"; keeping it always visible would leave a full extra line under every user bubble. Touches only the web; the fork flow itself (`handleFork`, `session_fork`) is unchanged.
3. **Timestamp moved out of the chrome, onto the action row's line.** The timestamp (and the Sending indicator) now sit under the bubble / under the assistant text on the same line as the action row, so no line is added for the actions. For a user bubble the actions sit left of the time so the time stays under the bubble's right edge. The assistant timestamp is muted grey instead of purple (the purple went with the bubble; the mockup shows it grey). The shipmates card's timestamp is under the card for the same reason.
4. **Width via per-row `max-w-[760px] mx-auto` and composer padding, not a wrapper.** Each message row (and "Load older messages") is centered at 760px inside the full-width scroll container, so the scrollbar stays at the window edge. `ChatInput.svelte` uses `px-[max(1rem,calc((100%-760px)/2))]` on its root (and the same inset on the drafts panel), so the border stays full width, no markup is re-indented (the composer task rewrites that file next), and the content lines up with the messages. With a classic (non-overlay) scrollbar the two columns differ by half a scrollbar width.
5. **Chip status glyphs.** ✓ (done, emerald), ✗ (failed, rose), ⊘ (interrupted), ⟳ spinning (running, amber), matching the mockup instead of today's ✅ / ❌ / ⚡ emoji; the duration drops its "Took" / "Elapsed" prefix (the tooltip still says which). The chip border is amber while running and rose on error; the hide-tools "Running tool" row and the first-class `attach_file` / `say` cards are unchanged.
6. **New pure helpers `messageLayout()` and `toolChipStatus()`** in `web/src/lib/components/chat-message-helpers.ts`, with the first unit tests for that module (`chat-message-helpers.test.ts`, also covering `isFirstClassTool`, `shouldAutoExpand`, `toolDuration`). The layout names (`document`, `bubble`, `chip`, `card`) are local to the chat list; none clashes with a `CONTEXT.md` term.
