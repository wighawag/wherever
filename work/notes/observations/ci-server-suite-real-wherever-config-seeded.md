# CI server suite: the real ~/.wherever/config.json gets seeded by some test (2026-11-16)

Seen in CI runs 41280565482 (2026-11-01) and 43951253208 (2026-11-16), both server jobs (bundled and `pi ~1.4.0`): `server/test/assistant-scheduler-server.test.ts` failed its real-dir guard with `expected 'config.json:a68c7ff760161d86' to be 'ABSENT'`. So during the suite something wrote the runner's real `~/.wherever/config.json`. The content hash matches the default config that `getWhereverConfig()` seeds (`server/src/session-pool.ts`) whenever it runs with `WHEREVER_CONFIG_DIR` unset and no config file present. The guard only notices because the runner's home starts with no `~/.wherever`. It did NOT fail in run 43958381554, so it is intermittent (timing-dependent, or a test that only sometimes reaches that path).

Not reproduced locally: the whole server suite under a throwaway `HOME` (2026-11-16) left no `~/.wherever`, and the six test files that import pool/server code without setting `WHEREVER_CONFIG_DIR` (assistant-notify, assistant-tools, folder-existence-cache, remote-candidates, session-download-range, session-list-cache) each left none when run alone. Leads: a spawned child that inherits HOME without the config-dir env, a module-load-time `getWhereverConfig()` that runs before a `beforeAll` sets the env, or a CI-only environment difference (no web build, no git identity, `CI=true`). One way to find it: in CI, make `getWhereverConfig` (or a vitest setup file) log a stack trace when it seeds a default under `os.homedir()`.
