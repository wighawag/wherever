# Decisions taken while building `cli-assistant-tool-twins` (2026-10-30)

Recorded per the work contract so a reviewer can ratify or reverse them. Code sites: `extension/src/assistant-tool-twins.ts` (module JSDoc, `syncTwinActivation`, `ASSISTANT_TWIN_REQUEST_TIMEOUT_MS`), `extension/src/index.ts` (twin registration, `session_start` sync, `before_agent_start`), `server/src/assistant-tools.ts` (`assistantCliOps`, `ASSISTANT_NOT_CONFIGURED_ERROR`), `server/src/cli-requests.ts` (`CliCaller`, the twin ops), `server/src/index.ts` (`assistantHooks`, the `cli_request` caller). Documented in `CONTEXT.md` "The `assistant_*` tool twins in CLI-bridge sessions".

1. **The twins are active exactly while the cache is `configured`; EVERY other state deactivates them, and the extension also syncs at `session_start`.** The task says "deactivates them if a push says not configured". pi restores a resumed session's tool loadout from its transcript (`_restoreToolsFromTranscript`), so twins activated in an earlier run would come back active in a run whose server says not configured / is old / is disabled, or that has no server at all, which would break "a disabled assistant leaves the session exactly as today". The cache keeps the last server answer across a disconnect (`cli-bridge-foundation` decision 2), so a live session does not lose its twins on a socket drop; they fail at call time. Alternative: deactivate only on a `not_configured` push (leaves transcript-restored twins active against an unconfigured server). Touches `cli-bridge-foundation`'s cache semantics (read only, unchanged).
2. **"Configured" means `assistant_info` reports a folder, which the server gates on `active`** (`cli-bridge-foundation` decision 1). So a server refused by another server's folder lock leaves the twins inactive, unlike server sessions, whose schedule tools stay registered with a lock-state error. If a twin is called while the server is configured but not active (the state changed after activation), the op answers the same lock-state error, `notify` included (a server session has no `assistant_notify` then; a twin cannot be hidden server-side, so it gets the schedule tools' error). Touches `assistant-schedule-tools-server` / `channel-seam-notify-and-web-push` (same hooks, same gates).
3. **Twin-op timeout is 30 s** (`ASSISTANT_TWIN_REQUEST_TIMEOUT_MS`), not the 10 s default: these ops do real work (a `schedule.json` write behind the scheduler's queue, `assistant_notify`'s delivery to every push service, which has no fetch timeout of its own). An old server is already recognised by `assistant_info`'s 10 s timeout before the twins can ever activate, so the longer timeout costs nothing there. Unref'd like every bridge timer.
4. **Wire shape: a twin op answers `ok: true, result: {text, details}`** (the server tool's result) and an error as `ok: false, error` (the op's error string). The twin returns `isError` with `"<tool name>: <error>"`, the server tools' `toResult` format. A disconnected bridge's message gains "this cannot run until the bridge reconnects". New user-visible error: `ASSISTANT_NOT_CONFIGURED_ERROR` for `assistantFolder` unset (reachable only through a raw `cli_request`, since the twins are inactive then).
5. **The caller is the pool's entry for the registered session** (`sessionId`, `cwd`, `sessionFile`); `CliCaller` gains optional `sessionId` / `cwd`. A connection whose entry the pool no longer has (no `cwd`) is refused rather than stamping a blank origin (a new refusal, "no longer registered; reconnect").
6. **One hooks object for both paths.** `server/src/index.ts` keeps the `AssistantSessionHooks` it gives the pool in `assistantHooks` and hands the same object to `createCliRequestRouter`, so server tools and twins share gates and backends by construction.
7. **The twins' text, parameter schemas and `timezoneLine` live in a new pi-runtime-free module** (`extension/src/assistant-tool-twins.ts`) that the server drift test IMPORTS (like `conversation-mode-hint.test.ts`), instead of parsing `index.ts` source like `say-tool.test.ts`. The drift test also compares the parameter schemas (the task only names texts), since a schema drift breaks a twin just as surely.
8. **The CLI timezone line uses `ctx.cwd` of the turn and `path.resolve` equality**, like the server (the symlink caveat in `assistant-folder-symlink-cwd-mismatch.md` applies equally). It is appended after the conversation-mode hint, matching the server's extension order.
9. **Changeset bumps are `minor`** for both packages (new tools in terminal sessions, new protocol ops).
