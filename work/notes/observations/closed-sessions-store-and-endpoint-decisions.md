# closed-sessions-store-and-endpoint: decisions (2026-11-24)

In-scope choices made while building the closed-sessions store and `POST /sessions/close` (task `closed-sessions-store-and-endpoint`, ADR 0025). Ratify or reverse.

1. **Cap numbers.** `MAX_CLOSED = 20_000` entries and `MAX_CLOSED_FILE_BYTES = 8 MiB` (`server/src/session-closed.ts`). 20,000 pretty-printed entries with ~150-char paths are about 5 MB, so 8 MiB matches the entry cap with headroom. The same byte limit is the read guard: a file found above it is treated as corrupt (fail closed), and the store never writes above it. Alternative: a tighter byte cap (e.g. 4 MiB) that could refuse before the entry cap with long paths.
2. **Refusal shape at the cap.** `ClosedCapError` ("Too many closed sessions (limit ...). Delete or reopen some closed sessions first."), answered as HTTP **409** with `{error}`. A corrupt store stays 500 (`ClosedUnavailableError`), like stars. Pruning runs only when over the cap and drops only entries whose transcript `fs.existsSync` says is gone; the sessions being closed by the current request are protected (their transcript may not be written yet, like a star from the top bar). Alternatives: 507 Insufficient Storage, or 400. Touches the sidebar task, which must surface the message.
3. **`unstarred` representation.** `unstarred: true` is present only when the close removed a star; otherwise the key is omitted (a parsed `unstarred: false` is dropped). It is computed from `readStarredSet()` (never throws), so with a corrupt stars file the close succeeds and records no `unstarred`. Touches the undo task.
4. **Response shape.** A close answers `{batch, sessions}` where `batch` is a fresh `c_<16 hex>` id per request and `sessions` lists the sessions THIS request newly closed (a re-close of an already closed session answers a fresh batch with `sessions: []`, and the stored entry keeps its original `closedAt`/`batch`, mirroring how a re-star keeps `starredAt`). A reopen answers `{batch: null, sessions: [reopened]}`. Touches the undo and cascade tasks: undo should reopen the entries carrying its batch.
5. **Listing flag wiring.** `closed: true` is stamped by the pool (`buildFolders`) from an injected `getClosed` option beside `getStarred`, rather than in the `/sessions` handler, so every listing path marks it the same way. `getClosed` never feeds the scan's retention `keep`.
6. **Star endpoint reopen is best effort.** `POST /sessions/star {starred: true}` writes the star first, then reopens best effort (logged); a corrupt closed store does not block starring. Unstarring never touches the closed store.
7. **Store module name.** `server/src/session-closed.ts`, beside `session-stars.ts`.
