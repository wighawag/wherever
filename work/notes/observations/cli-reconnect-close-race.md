# CLI bridge reconnect can be unregistered by the old socket's close (2026-10-30)

Seen while testing `cli-bridge-foundation` (`server/test/cli-bridge-foundation-server.test.ts`, failed once under full-suite load before the test waited for teardown): `ws.on('close')` in `server/src/index.ts` calls `sessionPool.unregisterCliSession(client.sessionId)`, and `unregisterCliSession` removes whatever CLI entry holds that file without checking that its `cliWs` is the CLOSING socket. If the bridge's reconnect `cli_register` lands before the old socket's close handler runs, the fresh registration is deleted and the session is no longer resident (a real terminal would then sit unregistered until its next reconnect). A guard like `tracked.cliWs === closingWs` would close it; not changed here (out of scope).
