# live-strip-two-line-rows: decisions (2026-11-25)

Decisions taken while building task `live-strip-two-line-rows` (spec `sidebar-compact-layout`, stories 5 to 10). Each touches only the Live strip (`web/src/lib/components/LiveStrip.svelte`) and its pure helpers (`web/src/lib/core/live-sessions.ts`).

1. **`LiveSessionRow.stateText` replaced by `waitingOn: string | null`.** The badge no longer carries "waiting on <session>", so the field that held it would have changed meaning; it is renamed to what it now is (the waited-on text for a `waiting-for-session` row, null otherwise) and the short badge is a separate pure helper, `liveBadgeText`. Alternative: keep `stateText` and re-mean it as the badge text; rejected as a silent re-meaning. Only `LiveStrip.svelte` read the field.
2. **A `waiting-for-session` row always shows its waiting-on text on line two, even the fallback "waiting on a session", and then never its status line.** The spec says "waiting on <session>, else the presence status line"; read literally, the waiting-on part exists for every waiting-for-session row (as the badge did before), so behaviour for that row is unchanged except where it is drawn. Alternative: show the status line when the waited-on session cannot be named; rejected to keep the old information and a simple rule.
3. **The folder is shown on every row's second line**, including the waiting-for-session row, where `live.png` omits it. The spec composes "folder · ..." for every row and the spec wins over the mockup.
4. **Amber wash vs open-session highlight.** A waiting-for-you row is washed amber (`bg-amber-400/10`); when it is also the open session the wash is stronger (`/20`) instead of turning grey, so the row never loses its "needs you" colour. Other open rows keep today's grey highlight.
5. **`liveStripHeader` is kept as the header's tooltip and accessible name.** The visible header is "LIVE" plus count dots; the text form still gives screen readers and hover a sentence. Alternative: delete it; rejected since the dots alone have no sentence-level accessible name for the button.
6. **`liveStateCounts` lives in `live-sessions.ts` and the strip composes it with `liveCountDots` from `state-dot.ts`**, rather than adding a strip-specific dots helper to `state-dot.ts` or importing `state-dot.ts` from `live-sessions.ts` (which `state-dot.ts` already imports, so that would be a cycle).
