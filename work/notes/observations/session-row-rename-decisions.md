# session-row-rename: decisions (2026-11-25)

Non-obvious in-scope choices made while building task `session-row-rename` (spec `sidebar-compact-layout` story 39). Each is easy to reverse.

## Drift check

The dependencies landed as the task assumes: `session-row-menu` left room for Rename after Star in `rowMenuItems` (its doc said so), the shared `Menu` / `MenuItem` primitive is in `web/src/lib/components/menu/`, and `rename-session-endpoint` exported `renameSession(sessionFile, name)` from `web/src/lib/session-store.ts`, not optimistic, rejecting with the server's text (`RENAME_REFUSALS` in `server/src/session-rename.ts`). No drift found.

## Decisions

1. **The prompt is a native modal `<dialog>` (`showModal()`), not an inline field in the sheet / popover.** It sits in the top layer, so neither the phone drawer's transform (the containing block of `fixed` descendants, which confines the bottom sheet to the drawer) nor the sidebar's scroll box clips it, and the chat ⋯ can mount the same component anywhere. It is centred horizontally and placed 15vh from the top (not vertically centred) so a phone keyboard does not cover it. Alternative: an inline field replacing the Rename item inside the menu (stays inside the menu's lifetime, so a refusal would have to keep the menu open; awkward in the popover's 14rem width for the long refusal texts).
2. **The row owns its prompt, mounted only while open.** `SessionRow.svelte` renders `RenamePrompt` (inside `{#if open}` in the component), so there is one dialog in the DOM at a time, not one per row, and `+page.svelte` is untouched. `SessionBrowser.svelte` passes `onRename={readOnly ? undefined : renameSession}`; the row hides Rename without `onRename`, and `rowMenuItems` leaves it out on the read-only page, so both layers agree.
3. **An unchanged name cancels like an empty one** (`renamePromptAction`): nothing is sent, so re-confirming the prefilled name does not append a redundant `session_info` line. The comparison uses the server's cleaning rule (whitespace runs collapsed, trimmed), copied in `normalizeSessionName`; the server stays the authority on validity (length cap included), so the client does not check the 200-character cap and a too-long name shows the server's message.
4. **A refusal keeps the prompt open with what was typed**, the error under the field (`role="alert"`), the field re-focused; typing clears the error. A save that answers after the prompt was closed is ignored (attempt counter). No optimistic rename (the name arrives through `sessions_updated`), so there is nothing to roll back.
5. **Prompt wording:** title "Rename session", the row's label under it (the current name, else the first-message preview, so the user knows which session when the field is empty), and the hint "An empty name cancels." The mockups only show the ✎ Rename item, not the prompt.
6. **Clicks, pointer-downs and keys stop at the dialog.** It is in the top layer but still inside the row in the DOM, so without this a key (Escape) or click would also reach the row's / page's handlers.

## Browser check

Ran this branch's real server through the test harness (`server/test/harness.ts`: temp agent, config and state dirs, the fake LLM, no token) with five sessions written in its temp sessions dir: one only on disk (named), one opened from the web (a server session in the pool), one CLI-bridged by a fake bridge advertising `cli_rename` and streaming (so it is in the Live strip; the fake bridge appended the `session_info` line as pi's `setSessionName` would and answered `ok`), one bridged without the capability (old extension) and one with no message. Served the built web and drove headless Chromium over CDP; then stopped the server and Chromium and removed the temp files.

- Desktop 1280x800: hovering a row shows ⊘ and ⋯; the popover lists Close, Star, Rename, Copy link, Open in new tab, then Delete… apart. Rename opens the dialog centred over the page with the dimmed backdrop, the field prefilled "Disk named", focused and selected. Typing a name and Enter closed it and the row read "Renamed on disk" after the relist (disk path). The opened session (server in the pool, one client) renamed to "Pool renamed" the same way. Escape after typing closed the prompt without renaming and left the open chat in place.
- Phone 390x844 (touch emulation), in the drawer: the sheet lists Close, Star, Rename, Copy link, Delete… (no Open in new tab). Rename on the unnamed bridged session opened the prompt with an empty field over the drawer; Enter renamed it, and both the folder row and the Live strip read "Terminal renamed" (CLI path). The old-extension session showed "This session runs in a terminal pi whose wherever extension is too old to rename it. Update the wherever extension in that terminal (@wherever-dev/pi), then try again." in red under the field, the prompt stayed open with the typed text, and the row kept its name; Escape closed it. The empty session showed "This session has no message yet, so a name would not be saved. Send a message first, then rename it."; clearing the field and pressing Enter then closed the prompt with no request.
- Read-only page: the harness has no read-only sessions, so no row could be checked there; `rowMenuItems` (unit-tested) and the `readOnly` guard on `onRename` keep Rename off it.
