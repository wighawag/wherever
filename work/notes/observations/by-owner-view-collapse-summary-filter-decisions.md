# Decisions: by-owner-view-collapse-summary-filter (2026-11-24)

In-scope choices made while building task `by-owner-view-collapse-summary-filter` (spec `session-list-by-owner-view`). Code site: the module JSDoc of `web/src/lib/core/owner-tree.ts` (rules 8 and 9) and the helpers below it.

1. **`hasMatch` is false when the filter is empty.** It means "a filter is set and this group holds a match", the input that forces the group open (`ownerGroupExpanded` = `hasMatch` OR not saved collapsed). Groups without a match are dropped by `ownerTree` itself, so every returned group would otherwise have `hasMatch` true. Alternative: always true without a filter (then the expanded rule would need the filter text too). Touches only the By-owner view.
2. **`matched` is true on every visible node when the filter is empty** (the empty filter matches all, as `sessionMatchesFilter` does). The row's `dimmed` is `!matched && !closed`, so a closed context row stays rendered as closed, and nothing is dimmed without a filter.
3. **Non-matching descendants of a match are dropped**, as in the folder view (which keeps only matches). The spec only asked that ancestors be kept as context. Alternative: keep a match's whole subtree.
4. **The summary is counted before the filter**, over the closed-pruned group, so a collapsed head and the amber attention describe the whole orchestration, not the filtered rows. Groups also keep their whole-group order (story 8) while filtering.
5. **Summary text leaves out idle and zero counts**, order: running, waiting for you, waiting on a session (the spec's example order). Labels come from `stateLabel`. "1 session" singular.
6. **Collapsed state is one `localStorage` key**, `wherever-owner-groups-collapsed`, a JSON array of collapsed root paths; groups are expanded by default (the previous task rendered them all expanded). On save the array is pruned to sessions in the current listing so it does not grow forever. Alternative: one key per root path (`wherever-owner-group-collapsed:<path>`), which never gets cleaned up.
7. **Only a group with children is collapsible**: a group of one has no chevron and no summary (nothing to fold). Its head is still amber when it waits for you.
8. **While the filter forces a group open, its chevron is disabled** (tooltip says why), instead of a transient per-search override like the folder view's `searchExpanded`. This keeps "typing a filter never rewrites the saved collapsed state" trivially true and avoids a click that changes a state the user cannot see. Alternative: mirror `searchExpanded` with a search-only collapse.
