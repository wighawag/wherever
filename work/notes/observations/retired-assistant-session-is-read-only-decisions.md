# Decisions taken while building `retired-assistant-session-is-read-only` (2026-11-17)

Recorded per the work contract so they can be ratified or reversed. Code sites: `server/src/assistant-controller.ts` (`isRetired`, `isFolder`), `server/src/index.ts` (`hasHardReadOnly`, `folderHasOtherViewedSession`, `resolveFolderConflictState`, `refreshRetiredViewers`, `session_load` / `session_new` / `message`), `server/src/protocol.ts` (`assistant_retired`, `session_created.assistantRetired`), `client/src/client.ts`, `web/src/routes/+page.svelte`.

1. **With no pointer yet, every session in the assistant folder is retired.** ADR 0020 says "not the current pointer session"; with no pointer none is current. Opening the Assistant (`assistant_open`) creates and points at one, which is exactly the notice's action. Alternative: nothing is retired until a pointer exists (old sessions in a folder newly made the assistant folder would stay writable and fork the conversation). Touches the session list (opening an old session there is read-only).
2. **New server frame `assistant_retired { sessionId, retired, readOnly }`** for the live change, plus `assistantRetired: true` on `session_created` for the load-time verdict, mirroring `folder_missing` / `folderMissing`. Alternative: let the web derive "retired" from `assistant_status` and its own session file; rejected because read-only is the server's verdict (the client never invents one). "Retired" reuses the controller's existing term (`retire()` of the replaced pointer session), so no new concept is coined.
3. **The verdict is keyed on the PAINTED session** (`paintedSessionFile` / `paintedCwd`), not the attached one, so a cold load still building when the pointer moves is re-evaluated too; the late attach re-derives read-only from `client.assistantRetired`. The flag is cleared with the painted session (`clearPaintedSession`).
4. **A retired session is no party to a folder conflict**: `resolveFolderConflictState` reports `active: false` for it and `session_load` never marks it `folderConflict`, so it shows one banner (retired) rather than two. A retired session is also skipped as an occupant (`folderHasOtherViewedSession`, and `SessionPool.detectConflict` gained an optional `ignore` predicate).
5. **`session_new` in the assistant folder awaits `controller.idle()`** before computing its verdict: the pool's session-created callback moves the pointer on the controller's serial queue, after `createNewSession` returns. Only for that folder, because the queue can hold a seconds-long cold load (`send`) that no other create should wait behind.
6. **Live un-retire is supported** (the pointer moving ONTO a painted session, e.g. a terminal `pi` registering `isNew` while a tab views it): read-only is re-derived from the remaining reasons. Rare, but it keeps the verdict symmetric.
7. **`POST /session/upload` is unchanged.** It has no socket, so no web viewer verdict applies (the same accepted limitation as the folder-conflict lock, ADR 0012); the WebSocket upload paths refuse through `client.readOnly`.
8. **The refusal text for a send** names the reset and points at the current assistant session instead of "Continue anyway".
9. **Changeset bump is `minor`** (new user-visible web behaviour and a new protocol frame), as the task asked.
