# Decisions: folder-header-menu-and-close-all (2026-11-25)

Non-obvious in-scope choices made while building task `folder-header-menu-and-close-all` (spec `sidebar-compact-layout` stories 25 to 27, 44). Each is easy to reverse.

1. **`sessionFiles` is close-only and never cascades.** `POST /sessions/close {sessionFiles, closed: true}`; `closed: false`, `cascade`, or mixing with `sessionFile` / `batch` is a 400. Why: the only caller is "Close all in folder", whose spec says no cascade, and the undo already has its own form (`{batch, closed: false}`). Alternative: also accept a multi reopen; not needed by any story. Touches: `validateCloseInput`, `docs/USAGE.md`.
2. **Cap `MAX_CLOSE_FILES = 1000`.** Why: a folder rarely holds more than a few dozen sessions (the mockup's largest is 47); 1,000 bounds one request's work while never limiting a real folder. Alternative: reuse `MAX_CLOSED` (20,000), too loose for one request.
3. **One bad path rejects the whole request (400, nothing closed).** Why: the same check as a single close, and a partial close would make "one Undo" confusing. Alternative: skip bad paths and close the rest. Duplicates are silently deduplicated.
4. **Close all in folder skips the owned-session question.** It calls `closeFolder` (no `/sessions/owned` lookup), per the spec's "no cascade to owned sessions elsewhere". The current session is not left when it is among the closed ones (a single close does not leave it either).
5. **The menu item shows the count it would close and is disabled at 0** (title "No open session shown in this folder"). Why: the action skips closed rows, so a folder showing only closed rows (Show closed on) would otherwise offer a no-op. The mockup shows no count; the hint is muted and small.
6. **Delete all asks again in place**: "Delete all…" (`keepOpen`) swaps into "Delete N sessions?" plus Cancel inside the same menu, the confirm taking the focus (`focusOnMount`); closing the menu cancels. Alternative: a separate dialog. In-menu keeps today's two-tap flow and the "asks again" hint of the mockup.
7. **Shared menu: the sheet is `fixed` inside the drawer, not portalled to `<body>`.** The translated phone drawer is the containing block, so the sheet spans the drawer (as in `sidebar.png`). A portal would move nodes outside Svelte's delegated-event root and break `onclick`. The popover is `absolute` and flips above its trigger when there is no room below; it can still be clipped by the sidebar's scroll area in an extreme case. Later users of the menu (row ⋯, chat ⋯) should know this.
8. **☰ view options toggles keep the menu open** (`MenuItem checked keepOpen`), Refresh closes it, and Refresh no longer shows its spinner (the menu is gone by then). The By folder / By owner switch stays a custom segmented control inside the menu (`data-menu-item` for arrow keys).
