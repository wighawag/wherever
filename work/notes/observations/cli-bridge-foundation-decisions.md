# Decisions taken while building `cli-bridge-foundation` (2026-10-30)

Recorded per the work contract so a reviewer can ratify or reverse them. Code sites: `extension/src/bridge-requests.ts` (module + `AssistantInfo` JSDoc), `extension/src/index.ts` (`pendingIsNew`, `requests`, `assistantInfo`, the `agent_settled` handler), `server/src/cli-requests.ts` (module + `AssistantInfo` JSDoc), `server/src/session-pool.ts` (`registerCliSession`, `getCliCapabilities`), `server/src/index.ts` (`cli_request` case, `currentAssistantInfo`, `pushAssistantInfoChanged`). Documented in `CONTEXT.md` "CLI bridge request/response and registration details".

1. **`assistant_info` answers `ok: true` with `{ assistantFolder: string | null }`**, null meaning "not configured", rather than `ok: false, error: "not configured"`. Same shape as the `assistant_info_changed` push, so one parser serves both, and `ok: false` stays reserved for real failures. The gate is `assistant.active` (configured AND lock held), so a server refused by another server's lock also answers null. Touches `cli-assistant-tool-twins` (activates on `configured`) and `assistant-schedule-tools-server` (adds `timezone` to the same result).
2. **The extension cache's states** are `configured {assistantFolder, timezone}`, `not_configured`, `unsupported` (request timed out, or the server refused the op), `disconnected` (no server has answered yet) and `disabled` (`remote.bridge: false`). A disconnect AFTER a server answer keeps that answer, so active tool twins stay active and fail at call time with "not connected" (ADR 0016 "a call still fails clearly at call time") instead of vanishing mid-session. Alternative: drop to `disconnected` on every socket drop (tools would flicker on each reconnect). Touches `cli-assistant-tool-twins`.
3. **`assistant_info` is fetched after EVERY register, not once per process.** A reconnect may be to a restarted server with a different config. "Once after register" in the task is read as once per register. A push that arrives while a refresh is in flight wins (generation counter).
4. **Request timeout is 10 s** (`DEFAULT_BRIDGE_REQUEST_TIMEOUT_MS`), overridable per request. Long enough for a busy server, short enough that an old server is recognised within a turn; unref'd, so it never delays `pi -p` exit. Touches `cli-assistant-tool-twins` (may pass a longer per-op timeout).
5. **`isNew` is consumed only by a register that was actually handed to an open socket**, and kept until then: a `pi` started while the server is down still moves the pointer on its first successful register. `sessionHasNoMessages` answers false on an unknown surface or a throw (wrongly claiming new would move the pointer).
6. **The server fires the session-created callback for `isNew` only when the pool had no entry for the file**, mirroring "only on a real creation". A CLI-created session moves the pointer exactly like a web `/new` in the folder, which RETIRES the previous assistant session (aborts its running turn, clears its queue), as `assistant-pointer-and-reset` established for `handleSessionCreated`.
7. **New `registerCliSession` options are an options object** (`opts: { isNew?, capabilities? }`) after the existing positional `isStreaming`, rather than two more positionals. `capabilities` is stored on the CLI entry and read with `getCliCapabilities(file)` (for `assistant-scheduler`'s `agent_end` fallback).
8. **A `cli_request` from a connection that never sent `cli_register` is refused** with an error naming `cli_register` (a new refusal; the caller must be server-resolved). A request without a string id is dropped (nothing to correlate an answer with).
9. **`pushAssistantInfoChanged` exists in `server/src/index.ts` but nothing calls it yet**: nothing changes the info at runtime in this task (`assistantFolder` takes effect on restart, and a bridge re-asks on every register). `assistant-schedule-tools-server`'s timezone setter is its first caller.
10. **Changeset bumps are `minor`** for both `@wherever-dev/pi` and `wherever-dev` (new protocol surface and a user-visible behaviour: a terminal `pi` in the assistant folder becomes the current assistant session).
