# Decisions taken while hardening the assistant drive: CLI reconnect race, symlinked assistantFolder, openssl, CORS (2026-10-31)

Recorded per the work contract so a reviewer can ratify or reverse them. None met all three ADR criteria (each is cheap to reverse). Code sites: `server/src/session-pool.ts` (`unregisterCliSession`, `scheduleIdleCheck`), `server/src/index.ts` (WS `close`, `currentAssistantInfo`, `corsAllowMethods`, the self-signed fallback), `server/src/assistant-folder.ts` (`canonicalPath`, `isSameFolder`), `server/src/assistant-controller.ts`, `server/src/assistant-tools.ts`, `extension/src/assistant-tool-twins.ts`, `server/test/require-binary.ts`. Documented in `CONTEXT.md`.

1. **`unregisterCliSession(file, closingWs)` takes the closing socket as a REQUIRED argument**, not an optional one, so no future caller can skip the ownership check by omission. A close from a socket that no longer owns the entry is a silent no-op (no log): it is the expected outcome of a reconnect that won the race. The superseded socket A is not closed by the re-register; it closes on its own and its teardown is now harmless.
1b. **The handoff order (old socket closes first, a viewer attached) is fixed in three places**, found by review: `registerCliSession` awaits a pending `loadSession` for the file and re-checks the pool after its own header await (restarting the register if an entry appeared), `loadSession` disposes its freshly built agent and returns the existing entry if one appeared during the build, and `unregisterCliSession` hands the viewers to whatever entry holds the file after the reload (and emits no "terminal disconnected" when that is a reconnected CLI). Alternative considered: only one of these; each closes a different interleaving, and the cost is one await on a path that is otherwise unchanged. Because that await can last a whole agent build, `registerCliSession` refuses (returns an error) when its socket is CLOSING or CLOSED after a wait: that socket's close teardown already ran and found nothing to remove, so registering it would leave a dead entry the viewers stay attached to. The check is "closed", not "!== OPEN", so a socket without a `readyState` (test fakes) still registers.
2. **The idle timer checks it still belongs to the pool's current entry** before destroying. Today `registerCliSession` already cancels the old entry's timer, so this is belt and braces for any future path that replaces an entry without cancelling. Pins (`pinSession`) are keyed by session file, so they survive a reconnect unchanged; nothing to fix there.
3. **`canonicalPath` realpaths the deepest EXISTING ancestor and appends the rest**, a superset of "realpath when it exists, else resolve": a not-yet-created `jobs/` under a symlinked folder still canonicalises under the target. A path with no existing ancestor is plain `path.resolve`. The extension has a twin (`KEEP IN LOCKSTEP` comments on both), since it cannot import server code.
4. **Only COMPARISONS are canonical.** The controller keeps the configured spelling for creating sessions and in the pointer record, and `GET /config` `assistant.folder` still shows the configured path, so nothing user-visible changes for a non-symlinked folder. The pointer record is compared with `isSameFolder`, so switching the config between the link and its target keeps the pointer.
5. **`assistant_info` (and `assistant_info_changed`) send the folder CANONICAL.** The bridge compares it with a terminal pi's real cwd, and a bridge is not guaranteed to share the server's view of the link. The extension ALSO canonicalises both sides, which keeps an older server (sending the configured spelling) working on the same machine. Alternative rejected: send the configured path and rely on the extension's realpath alone (breaks whenever the bridge cannot resolve the server's link).
6. **CORS: one header, conditioned on Web Push running**, rather than DELETE advertised per path (only on `/push/*`). It restores the exact pre-#96 header with the assistant off, which is the guarantee that matters; per-path would be tighter but changes the header shape for no client that needs it.
7. **The openssl observation is discharged by deletion, not annotated "resolved"**, as the work contract requires for notes. Its root cause (a `bash -c` whose stdin is a socket sources `/etc/bashrc`, which resets PATH on NixOS; fixed in dorfl and my-boxes) is external ground truth, so it lives on as `work/notes/findings/bash-c-with-socket-stdin-sources-bashrc-and-resets-path.md`, which the fail-fast message points at.
8. **The server's openssl fallback stays a fallback** (plain HTTP with a warning, as before); only the message changes, naming the missing binary and the three ways out (`nix develop`/install, `--ssl-key/--ssl-cert`, `--no-ssl`). Making a missing openssl fatal would change boot behaviour for every default install.
