# Decisions: live-strip-names-the-session-waited-on (2026-11-24)

Drift check: shipmates core does not expose the waited-on session itself (no such field on `Presence` or API in `shipmates/dist/*.d.ts`), and `@shipmates/pi` still sets `waitingOn` to the question id on `waiting-for-session` (`tools.ts` `setToolState('waiting-for-session', qid)`), so the task's premise holds.

1. **Where the "waiting on X" text shows: in the state badge itself.** A `waiting-for-session` row's badge reads "waiting on <label>" (new `LiveSessionRow.stateText`) instead of a separate span next to a "waiting on a session" badge, which would say the same thing twice. The badge gained `max-w-[40%] truncate` so a long label cannot push the row out. Alternative: keep the badge and add a second text span. Touches only `LiveStrip.svelte`; the folder list's presence line (`presenceLine`) is unchanged and still says "waiting on a session".
2. **Label of the waited-on session: first role, else name, else first-message preview, else the fallback.** Same order as the strip's own row label (story 4), except that the folder-row label's "Empty session" is NOT used: "waiting on Empty session" reads as a bug, so an unnamed, empty session falls back to "waiting on a session". Alternative: the sidebar's `sessionLabel` (name / first message / `seenLabels` / "a session"); rejected because its `seenLabels` fallback would reveal hidden sessions (acceptance criterion), and it ignores roles. Code site: `waitingOnText` in `web/src/lib/core/live-sessions.ts`.
3. **"In the current listing" means the whole unfiltered listing,** not only rows the filter box shows: a session filtered out by the query is still listed (not hidden), so it is named. Code site: `liveSessions` builds `listed` from all folders.
4. **Server lookup is wrapped per presence (`waitingOnSessionOf` catches and returns null)** so one bad question cannot reach `snapshot()`'s catch, which would empty the inbox and presence. The role case uses `roleHolder`, never `resolve()`.
