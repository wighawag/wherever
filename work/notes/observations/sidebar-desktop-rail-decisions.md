# sidebar-desktop-rail: decisions (2026-11-25)

Task `sidebar-desktop-rail` (spec `sidebar-compact-layout`, story 19 and resolved decision 2).

1. **A view tab on the rail whose view is already shown only expands.** The full sidebar's tabs go back to the list when the active one is tapped (`tapTab`); on the rail that would hide the very view the user expanded to see. Alternative: reuse `onTab` as is (toggle back). Touches only the rail (`onRailTab` in `+page.svelte`).
2. **✦ Assistant on the rail does not expand the sidebar.** The task says "a tab or + expands the sidebar and then acts", but the Assistant is an action that opens a chat, not a sidebar view (`sidebar-nav.ts` keeps it out of `SidebarTab`; in the drawer it closes the drawer). Expanding would only cover the chat it opened. Alternative: expand first, as for the view tabs; a one-line change if wanted.
3. **The amber dot counts listed sessions from both the main and the read-only listing.** A read-only (fleet) session waiting for the human still waits for you. Alternative: main listing only. The chat top bar's menu dot (later task) should pick the same input so the two dots agree.
4. **The dot sits right under », above the tabs,** as an amber dot with a halo (the legend's "waiting for you" look) and a tooltip / accessible name with the counts ("1 question for you, 2 sessions waiting for you"). It is not clickable; the 🙋 tab below it is the way in.
5. **The collapsed state is read on mount, not at init.** The page is prerendered with SSR, and Svelte does not patch a class attribute that differs at hydration, so a collapsed user sees the expanded sidebar for the first frame. Alternative: read at init and accept a stale class after hydration (wrong layout).
6. **The rail's + also leaves settings mode and switches to the main list** before calling `openNewSessionForm()`, because only the main-list `SessionBrowser` consumes the flag; the rail's tabs also leave settings mode.
7. **Storage**: key `wherever-sidebar-collapsed`, "1" when collapsed and no key when expanded (the Live strip's convention), with storage errors swallowed (`web/src/lib/core/sidebar-rail.ts`).
8. **Rail width 48px (`md:w-12`), no width animation.** The sidebar's existing transition is on transform only (the phone drawer).
