# sidebar-filter-row-view-options: decisions (2026-11-25)

Task `sidebar-filter-row-view-options` (spec `sidebar-compact-layout`, stories 20 to 24 and 44).

1. **Only starred in the folder view is a pre-filter, like the text filter (no context rows).** `folderListView` narrows each folder to its starred sessions before `buildForkTree`, so a starred fork of an unstarred session is listed on its own at depth 0. Alternative: put it in the `pruneForkTree` "shown" predicate (like Show closed), keeping unstarred ancestors as context. Rejected because the folder view only dims closed context rows (an unstarred context row would look like a normal row), and because a folder's "Delete All" (and the coming "Close all in folder", task `folder-header-menu-and-close-all`) act on every row the folder lists: context rows would be swept into them while the user believes only starred rows are shown. The task only asked for the context rule in By owner. Touches: `folder-header-menu-and-close-all` (its "shown rows" are then exactly the starred ones). Documented in the `folderListView` JSDoc.
2. **Only starred in By owner is part of the rule 9 match (new rule 10), not the rule 7 visibility.** So the group summary still counts the whole orchestration (rule 8 says the summary describes the group, not the rows a filter leaves), and an unstarred ancestor is dimmed context via `matched: false`. It does NOT set `hasMatch`, so it never forces a collapsed group open, matching the folder view where Only starred does not open folders. Alternative: force groups open like the text filter. Documented in the `owner-tree.ts` module JSDoc (rule 10).
3. **One `wherever-only-starred` key for the main list and the read-only page.** It is a device preference about the star; two keys would make the read-only page silently differ. Alternative: a separate read-only key.
4. **A blue dot on ☰ while Only starred (or, on the main list, Show closed) is on.** A narrowed list hidden behind a closed popover would otherwise look like missing sessions. Not in the mockup; small and easy to drop.
5. **Empty-state text "No starred sessions"** when Only starred leaves nothing and no filter text is typed.
6. **The create form stays at the top of the scrolled list** (where the old row opened it), and + scrolls the list to the top and focuses the folder path. Alternative: pin the form outside the scroll area, rejected because on a phone with the keyboard up the Create button could become unreachable.
7. **The opener for the desktop rail is a store flag**, `newSessionFormRequested` set by `openNewSessionForm()` in `session-store.ts`, consumed by the main-list `SessionBrowser` whenever it is mounted (so a request made while the sidebar is being expanded is not lost). Only the main list consumes it; the read-only page ignores it.
8. **The popover stays open after Refresh and after toggling an option** (so the ↻ spin and the checkbox change are visible); it closes on Escape, a press outside it, or opening the + form.
9. **Owned-children chips are not filtered by Only starred.** They describe the row they sit under; filtering them would hide what a starred owner spawned.

Seen at both widths: one row with the filter box, ☰ and a blue +; ☰ opens the popover under it, right-aligned, with By folder / By owner (shown once shipmates and an owner exist), Show closed, Only starred, a separator and ↻ Refresh, matching `sidebar.png` panel 4; a press outside and Escape close it. Only starred hid jolly-roger (no star), listed only starred rows, put a dot on ☰, was written to `wherever-only-starred` and still checked after a reload; in By owner it kept the unstarred owner dimmed above its starred worker while the Live strip still listed the running worker. + turned into ✕, opened the full form (folder path, model, git init) at the top of the list with the folder path focused; `openNewSessionForm()` called before the browser mounted opened the form on mount. The search-all link still appears for a 2+ character filter and hands the text over. Read-only page: no +, ☰ holds only Only starred and Refresh. Creating a session against a live server was not exercised: the submit handlers are unchanged, only the form's container moved.
