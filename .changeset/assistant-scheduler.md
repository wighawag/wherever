Add the assistant scheduler. With `assistantFolder` set (and this server holding the folder lock), the server fires the jobs listed in `<assistantFolder>/schedule.json` (`{ "jobs": [...] }`, each with a 5-field `cron` or a one-shot `at` date-time or `"now"`, an optional pinned `tz`, `mode` `inline` or `isolated`, a `prompt` and `enabled`). Inline jobs are delivered into the current assistant session once it has settled with nothing queued, as `[schedule:<name>] ...` (a `/command` prompt is sent as-is so skills and templates still expand); isolated jobs start at once, in parallel, in a fresh session in `jobs/`. Jobs without `tz` follow the user's current timezone (server state in the state dir, initialised to the system timezone). Run history goes to an append-only `assistant-runs.jsonl` in the state dir; `schedule.json` is never written with run bookkeeping. Malformed entries are logged and skipped without stopping the others, prompts starting with `!` are refused, and runs missed while the server was down fire once on restart if the latest is within the new `assistantScheduleGraceMinutes` window (default 60), otherwise they are skipped and recorded. After an aborted turn the assistant session's leftover queued messages are now cleared (and recorded) so scheduled jobs can be delivered again. With `assistantFolder` unset nothing changes.
