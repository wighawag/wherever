Server-created sessions no longer load the CLI bridge extension (`@wherever-dev/pi`). Since 0.18 the server runs the pi extension lifecycle for its own sessions, and with the bridge in the user's pi settings (the normal install) the bridge ran inside the server, registered the server's own session as a CLI terminal, got shut down by that takeover, disconnected, and the server reloaded the session, several times a second. Any turn in flight was aborted with "CLI terminal disconnected. Active execution was aborted." even though no terminal was attached. The server now filters the bridge out of every session it builds (new, loaded and reloaded), identified by the name in the nearest named `package.json` of the extension's resolved file (`@wherever-dev/pi`), not by a substring. Every other extension still gets `session_start` and `session_shutdown`. A real terminal `pi` still takes over and hands back as before. The server also marks its process with a `globalThis` symbol (never an environment variable, so it cannot leak into terminals or commands a session spawns), which newer bridge versions check. The `remote.bridge: false` workaround in config.json is no longer needed.
