Let agents manage the assistant's schedule and the user's timezone. With `assistantFolder` set, every server-built session (not only the assistant's) gets four tools: `assistant_schedule_add` (writes a job to the assistant's `schedule.json`, stamping the calling session as its origin; the job always runs as the assistant), `assistant_schedule_list` (every job with its state and last / next run, marking the caller's, plus done and invalid entries), `assistant_schedule_remove` and `assistant_set_timezone` (a validated IANA name). Bad input returns a tool error and writes nothing; on a server refused by the folder lock the tools answer a clear lock-state error. Every turn in the assistant folder (and its `jobs/`) now carries `User's current timezone: <tz>` in its system prompt. The web reports its browser timezone on connect, which becomes the user's current timezone when it differs; every timezone change is pushed to CLI bridges (`assistant_info_changed`) and to the web, `assistant_info` returns the timezone, and the sidebar's Assistant entry shows it. With `assistantFolder` unset nothing changes: no tools, no timezone line, and the web's report is ignored.
