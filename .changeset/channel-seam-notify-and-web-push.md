Make wherever a chat app for its assistant: push notifications and the `assistant_notify` tool. With `assistantFolder` set (and this server holding the folder lock), every server session gets `assistant_notify {title, body, navigateSessionId?, jobId?}`, the one way an agent reaches you proactively: it is delivered at once (even mid-turn) to every channel, and tapping it opens `navigateSessionId`, or for a scheduled job the session that scheduled it, or else the calling session. A scheduled turn that does not call it stays silent. The first channel is Web Push, sent by wherever itself (no extra service, no new dependency): turn on "Assistant notifications" in the settings on each device; the VAPID keys are generated on first use in the state dir, subscriptions are stored there behind the token, every subscribed device gets each push, and devices the push service reports gone are pruned. New optional config: `assistantWebPush` (`enabled`, default true; `subject`, the VAPID contact) and `publicUrl`. Clicking an in-app notification while the app is open now opens its session (it did not). Messages dropped by an assistant reset or an aborted turn are now attributed to the channel they came from, ready for Telegram. With `assistantFolder` unset nothing changes: no keys, no push routes, no `assistant_notify`, no settings toggle.
