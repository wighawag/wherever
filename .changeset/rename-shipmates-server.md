Rename: wherever's kenning integration now targets shipmates, the new name of kenning (shipmates spec D38). wherever depends on `shipmates` ^0.2.0 (was `kenning` ^0.1.1) and is the host for `@shipmates/pi` 0.3.0 or later; a session that still runs `kenning-pi` gets no inbox, presence, cards or spawn from wherever. What users must change: in pi's settings replace `npm:kenning-pi` with `npm:@shipmates/pi`; in wherever's `config.json` rename `kenning.enabled` to `shipmates.enabled`; rename the environment variables `KENNING_STATE_DIR` and `KENNING_POLL_MS` to `SHIPMATES_STATE_DIR` and `SHIPMATES_POLL_MS`. The shipmates database is now `$XDG_STATE_HOME/shipmates/shipmates.db` (was `.../kenning/kenning.db`), and wherever's own state files are `shipmates-notified.json`, `shipmates-children.json` and `shipmates-archives.json` (were `kenning-*.json`): nothing reads the old names, so rename the files in wherever's state dir by hand, with the server stopped, to keep their records. For WebSocket clients: the frames are `shipmates_update`, `shipmates_answer`, `shipmates_answer_result`, `shipmates_undo_delete`, `shipmates_undo_result` and `shipmates_delivery`, the history role and field are `shipmates`, and the socket parameter is `shipmates=1` (were `kenning_*`, `kenning` and `kenning=1`); the CLI bridge ops are `shipmates_host_info`, `shipmates_spawn` and `shipmates_stop`. The web shows "shipmates" wherever it said "kenning".
